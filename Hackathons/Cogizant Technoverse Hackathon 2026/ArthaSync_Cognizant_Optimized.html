S0 Stage 0 · Trigger & Early Exit 5 eliminates ~70% of pipeline runs on quiet ticks

STAGE 0Trigger & Early Exit — Hash-Based Gate

60s · 5 nodes · ~70% API cost reduction
NODE 1 Timer Trigger
Input
Fires the pipeline every 60 seconds, 24×7. The heartbeat of the entire system.
CONFIG
Interval:60s
TZ:Asia/Kolkata
Out:{tick_id, ts_utc, tenant_id}
NODE 2 Fetch Channel Snapshot
Knowledge Retrieval
Parallel fan-out pull from Shopify REST, Amazon SP-API, and POS CSV on S3.
CONFIG
Timeout:8s per source
Fan-out:parallel (3 threads)
Sources:Shopify · Amazon · POS S3
Out:{shopify:[], amazon:[], pos:[]}
NODE 3 Snapshot Hash Checkv2
Custom Code
MD5-hashes the snapshot, compares with Redis-stored previous hash. Kills 70% of runs.
CONFIG
Hash:MD5(json.dumps(snapshot, sort_keys=True))
Store:Redis SETEX 180s
Key:hash:{tenant_id}:last
Out:{changed: bool, hash: str}
NODE 4 Changed Since Last Run?
Condition
YES → Stage 1 (Sync Agent). NO → Node 5 (early exit). Binary gate.
CONFIG
Expr:$.changed == true
True branch:→ Node 6
False branch:→ Node 5
NODE 5 Quiet Tick Ack
Output
Writes a "skipped" metric row for dashboard observability. Terminal node on no-change path.
CONFIG
Table:tick_log
Out:{tick_id, status:"skipped", reason:"no_change"}

STAGE 1Sync Agent — Schema Harmonization

on-change · 4 nodes · deterministic work stays deterministic

Knowledge Retrieval

Output Formatter

S2 Stage 2 · Conflict Agent 14 detect · fix · escalate · learn · self-tune

STAGE 2Conflict Agent — Bandit Self-Tuning + Idempotency + Rate Limit

on-change · 14 nodes · most complex stage
NODE 10 Rule-Based Conflict Detect
Custom Code
Checks canonical JSON against conflict rules (price mismatch, oversell, stale listing). Thompson-sampled weights from Bandit Store.
CONFIG
Rules:price_mismatch · oversell · stale · qty_drift
Weights:from 10a (Bandit Store) per-tenant
Thresholds:from 10b (Tenant Calibrator) P85
Out:[{sku, rule, sev, est_loss_inr}]
NODE 10a Bandit Storev3
Memory (dashed)
Beta(α,β) per rule-tenant pair. Thompson samples a weight each run. Enables self-tuning.
CONFIG
Table:rule_posteriors(tenant_id, rule_id, alpha, beta)
Sample:np.random.beta(α+1, β+1)
Connection:dashed → Node 10
Updated by:Node 17a (Bandit Update)
NODE 10b Tenant Calibratorv3
Custom Code (nightly)
Computes P85 of tenant's own 30-day legitimate price moves. Tenant-specific thresholds, not industry averages.
CONFIG
SQL:percentile_cont(0.85) WITHIN GROUP (ORDER BY delta)
Schedule:nightly 02:00 IST
Writes:tenant_thresholds table
NODE 11 Severity Router
Classifier / Router
Tags each conflict LOW / MED / HIGH by estimated monetary impact. Routes to appropriate handling path.
CONFIG
HIGH:est_loss > ₹10,000
MED:₹1,000 – ₹10,000
LOW:< ₹1,000
NODE 12 Any Conflicts Found?
Condition
Short-circuits to Insight Agent when conflict list is empty. Saves all downstream processing.
CONFIG
Expr:len($.conflicts) > 0
No path:→ Node 18 (Insight)
Yes path:→ Node 13 (Loop)
NODE 13 Loop per Conflictv2
Loop
Processes each conflict independently — a bad row cannot poison the batch. Parallelism=5.
CONFIG
Mode:ForEach($.conflicts)
Parallelism:5
On error:continue (isolate failures)
NODE 13a Reserve Action Slotv3
Custom Code
UNIQUE constraint on action_log enforces exactly-once at the DB level. Idempotency key prevents double-fixes.
CONFIG
Key:md5(tenant|sku|type|channel|price|date)
DB:INSERT OR IGNORE INTO action_log
Duplicate:→ skip branch (no-op)
NODE 13b Token Bucket Checkv3
Guardrail
Per-tenant Redis leaky bucket: 50 tokens, refills 10/min. Empty = auto-mode OFF for safety.
CONFIG
Algo:Leaky Bucket (RFC 2698)
Capacity:50 tokens
Refill:10 tokens/min
Empty →route to Node 17 (human)
NODE 13c Auto-Mode Tripped Alertv3
Guardrail
Pages owner, posts dashboard banner, logs incident. Fires when rate limit exhausted.
CONFIG
Channels:Telegram + email + dashboard banner
Next:→ Node 17 (Human Handoff)
NODE 14 Post Resolution API
Tool
Calls Shopify PUT /variants or Amazon Feed API with idempotency key. Exponential backoff.
CONFIG
Shopify:PUT /admin/api/variants/{id}.json
Amazon:POST /feeds (SubmitFeed)
Retry:exp backoff ×3, jitter 200ms
Header:X-Idempotency-Key: {action_id}
NODE 15 Log to conflict_log
Memory
Immutable event row — Stage 3's retrieval source. Append-only, never updated.
CONFIG
Cols:ts, tenant, sku, type, sev, delta, resolved_by
Mode:INSERT only (immutable log)
NODE 16 Amount > ₹50K?
Condition
Human-in-the-loop gate for financially material fixes. Based on 3.5× avg daily SME revenue.
CONFIG
Threshold:est_loss_inr > 50000
Basis:3.5× avg daily SME revenue
Yes →Node 17 · No → Node 18
NODE 17 Telegram + SMS Handoffv2
Human Handoff
Telegram first; 5-min no-ACK → MSG91 SMS fallback. Tier-2/3 India reality: SMS wins when app fails.
CONFIG
Primary:Telegram Bot API
Fallback:MSG91 SMS (5min timeout)
Actions:APPROVE · SKIP
ACK →Node 17a (Bandit Update)
NODE 17a Bandit Update on ACKv3
Memory
On APPROVE → α+=1 (rule validated). On SKIP → β+=1 (rule over-fired). Closes the learning loop.
CONFIG
APPROVE:UPDATE rule_posteriors SET alpha=alpha+1
SKIP:UPDATE rule_posteriors SET beta=beta+1
Feeds:dashed → Node 10a (Bandit Store)

S3 Stage 3 · Insight Agent 12 cold-start ready · calibrated threshold · dual-layer fact-verify

STAGE 3Insight Agent — Explainable Daily Bullet

on-change · 12 nodes · most sophisticated ML patterns
NODE 18 7-Day Conflict History
Knowledge Retrieval
Rolling week of conflict_log — grounding context for the LLM. Anchors to real events.
CONFIG
SQL:WHERE ts > NOW() - INTERVAL '7 days' AND tenant=:t
Order:ts DESC · LIMIT 50
NODE 18a Cold-Start Gatev3
Condition
Routes new tenants (<7 days data) to peer cohort retrieval instead of thin own-data. Critical for Day-1 value.
CONFIG
Expr:history_days >= 7
True (>=7d):→ Node 19 (Few-Shot Prompt)
False (<7d):→ Node 18b (Peer Cohort)
NODE 18b Peer Cohort (Bayesian)v3
Knowledge Retrieval
Anonymized same-vertical cohort data. Bayesian shrinkage blends tenant + cohort by data maturity.
CONFIG
Blend λ:days_of_data / 7
Formula:λ·tenant_data + (1-λ)·cohort_data
Prompt flag:early_stage=true
NODE 19 Few-Shot System Promptv2
Prompt Template
2 worked examples (pricing drift, oversell) locking JSON shape. Prevents schema drift across runs.
CONFIG
Examples:pricing_drift · oversell (2 shots)
Out schema:{"bullet":"•...","confidence":0-1}
Max bullet:25 words, starts with "•"
NODE 20 Insight Agent LLM
LLM Step
Produces the single most-visible artifact — the daily business bullet. Low temp for consistency.
CONFIG
Model:Claude Haiku
Temp:0.3
Max tokens:120
Out:{bullet: str, confidence: float}
NODE 21 Confidence >= threshold?v2
Condition
Threshold is per-tenant (isotonic calibration), NOT fixed 0.7. Adapts to each merchant's signal quality.
CONFIG
Source:tenant_thresholds.confidence_min
Cold start:0.7 (default)
Yes →Node 23 · No → Node 22
NODE 21a Bullet Feedback Logv3
Memory (dashed)
Logs every (confidence, owner_accepted) pair. The training data for the isotonic calibrator.
CONFIG
Cols:ts, tenant, bullet_id, confidence, accepted (bool)
Feeds:dashed → Node 21b (Isotonic Calibrator)
NODE 21b Isotonic Calibratorv3
Custom Code (nightly)
sklearn.isotonic fit on feedback log. Threshold = lowest raw confidence where precision ≥ 0.9.
CONFIG
Lib:sklearn.isotonic.IsotonicRegression
Min samples:200 before fitting
Cold start:0.7 default
Writes:→ tenant_thresholds.confidence_min
NODE 22 30-Day Deep Historyv2
Knowledge Retrieval
Low-confidence fallback. Loops back to Node 20 once with richer context. Cap of 1 re-query enforced.
CONFIG
SQL:WHERE ts > NOW() - INTERVAL '30 days'
Max re-queries:1 per bullet
Loop flag:deep_retry=true (stops infinite loop)
NODE 23 Regex Fact-Verifyv2
Guardrail
Layer 1 of 2: catches fabricated ₹ values, INR formats, K-suffix numbers, case-insensitive SKU check.
CONFIG
Regex:(?:Rs\.?|₹|INR)\s?([\d,]+(?:\.\d+)?)[Kk]?
SKU check:re.search(sku, bullet, re.IGNORECASE)
Pass →Node 23a (LLM Judge)
NODE 23a LLM-as-Judge Verifierv3
Guardrail
Layer 2 of 2: second Haiku call extracts all claims; set-membership check. Independent verification (Zheng et al. 2023).
CONFIG
Pattern:LLM-as-Judge (Zheng et al. 2023)
Model:Claude Haiku (separate call)
Check:claims ⊆ conflict_log facts
Cost:~₹0.02/bullet
NODE 24 Dashboard JSON
Output
Payload React dashboard polls every 5s via Axios. Closes the feedback loop via dashed edge back to 21a.
CONFIG
Schema:{ts, bullet, confidence, conflicts_today, revenue_saved_inr}
Poll:React Axios every 5s
Feedback:dashed → Node 21a
